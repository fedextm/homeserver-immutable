## Immutable Home Server

## About

This instalation using Fedora CoreOS as baseline.

## System layer

Ignition config using for the first boot. Prepare iso file using

```bash
cd sys_layer

# Prepare iginition
butane --pretty --strict --files-dir=$PWD config.yml > config.ign

# Download stable CoreOS version
coreos-installer download --stream=stable --architecture=x86_64 --platform=metal --format=iso --directory=./

# Create ISO
coreos-installer iso customize --force --dest-device /dev/vda --dest-ignition ./config.ign -o ./homeserver14.iso ./ fedora-coreos-stable.iso

```

## System 

Prepare service layer. Build imagem with all necessary tools

```bash
cd service_layer

podman build -t ghcr.io/fedextm/homeserver:v01 -f Containerfile .

podman push ghcr.io/fedextm/homeserver:v01
```

## After Rebooting

Rebase service using after reboot to setup other services

```bash
ssh core@host

sudo systemcl start rebase.service

```


## Access to Kubernetes (kubectl from your workstation)

The admin kubeconfig is generated by KubeSolo on the host (not stored in git):

```
/var/lib/kubesolo/pki/admin/admin.kubeconfig
```

Copy it to your workstation (root-only file, so use `sudo cat`):

```bash
ssh core@192.168.250.3 'sudo cat /var/lib/kubesolo/pki/admin/admin.kubeconfig' > ~/.kube/kubesolo.kubeconfig
chmod 600 ~/.kube/kubesolo.kubeconfig

export KUBECONFIG=~/.kube/kubesolo.kubeconfig
kubectl get nodes
```

The `server:` field already points to `https://192.168.250.3:6443` (the IP is in `extraSANs`).

Do not confuse it with `service_layer/k8s/kubesolo-config.yaml` (`/etc/kubesolo/config.yaml`): that is the KubeSolo
daemon config, not a kubeconfig, and `kubectl` fails with it (`no kind "KubeletConfiguration" is registered`).

## Secrets (SOPS + age)

Secrets live in git encrypted (`*.enc.yaml`, rules in `.sops.yaml`). Flux decrypts them with the age key stored in the
cluster secret `flux-system/sops-age` (`decryption` block in `service_layer/k8s/flux-sync.yaml`).

The private key is NOT in git: `~/.config/sops/age/keys.txt` on the workstation. **Back it up** (password manager):
without it the secrets cannot be decrypted or edited.

```bash
# Install the key into a new cluster (once)
kubectl -n flux-system create secret generic sops-age --from-file=age.agekey=$HOME/.config/sops/age/keys.txt

# Read / edit a secret
sops -d apps/pihole/secret.enc.yaml
sops apps/pihole/secret.enc.yaml

# New secret: write plain YAML named *.enc.yaml, encrypt in place, add to the app's kustomization.yaml
sops --encrypt --in-place apps/<app>/secret.enc.yaml
```

Only `data`/`stringData` are encrypted. Never commit a `*.enc.yaml` before running `sops --encrypt`.
